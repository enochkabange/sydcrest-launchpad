## Framework skills

* **MDN Learning Area (S10), topic names only:** structuring content with HTML; CSS styling basics; CSS text styling;
  CSS layout; dynamic scripting with JavaScript; JavaScript frameworks and libraries; accessibility; design for
  developers; version control. Extensions: advanced JavaScript objects; client side web APIs; asynchronous JavaScript;
  web forms; understanding client side tools; server side websites; web performance; testing.
* **O*NET Web Developers (S11):** tasks around building and updating sites, testing for browser and device
  compatibility, improving performance, gathering user requirements and documenting work. In demand technology
  names include Git, TypeScript, React, Vue.js, jQuery, GraphQL, WordPress, Figma.
* **ESCO webmaster proxy (S12):** essential skills include implement front end website design, maintain responsive
  design, troubleshoot website, use markup languages, use scripting programming, use software libraries; essential
  knowledge includes style sheet languages, web programming and quality assurance methodologies; optional knowledge
  includes JavaScript, TypeScript, World Wide Web Consortium standards, ICT debugging tools, ICT performance analysis
  methods, web analytics.
* **web.dev Learn (S13):** separate courses exist for HTML, CSS, JavaScript, forms, accessibility, performance, images,
  design, PWA and testing, which supports giving forms, performance, offline, design to code and testing their own nodes.

## What the adverts demanded that the draft outline lacked, and what changed

1. **Testing** appears in 9 of 19 adverts, including entry roles (A1, A3, A15), and is an MDN extension module and an
   ESCO essential knowledge item. The draft had no testing node. **Added `testing`** under the quality section.
2. **Turning a Figma design into code** appears in 8 adverts (with Tailwind or a component library in 7), and MDN has a
   "design for developers" module. The draft had nothing on it. **Added `design-to-code`** under frameworks, covering
   reading a Figma file, spacing and colour tokens, reusable components, and when a CSS framework helps.
3. **TypeScript** appears in 10 adverts including the two entry level fintech and NSS roles. The draft marked it
   optional. **Made `typescript` core** and placed it right after React.
4. **State management** (3) and **REST APIs** (12) are covered inside `react` and `fetch-and-async`, not new nodes.
5. **Merged `setup-on-a-budget` into the `start-here` section node** to stay within 30 nodes. The section explanation now
   covers the free setup, so no learning was lost.
6. **Kept `nextjs` optional.** It appears in 8 adverts, but it builds on React and TypeScript, and a learner can be
   hireable for junior roles without it. Founder may want to make it core later.
7. Signals noted but **not given nodes**: React Native (5, a separate mobile path), Node.js and backend (5, the backend
   track covers it), GraphQL (2), Shopify or WordPress (2, mentioned inside `freelancing-for-smes`), AI coding assistants
   (2, mentioned with a caution inside `debugging`), SEO (1, mentioned in `semantic-html`).
8. Emphasis shifted toward low end Android and slow networks throughout: performance, images, offline, and testing
   with network throttling, per the SydCrest learner profile.

Final outline: 30 nodes (7 sections, 23 topics), all with lesson content.
